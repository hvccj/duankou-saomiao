# 面试讲解笔记

## 为什么使用 `QThread`？

端口探测是 I/O 等待操作，直接在 Qt GUI 线程中循环会阻塞事件循环，导致窗口无法重绘、按钮无法响应。`QThread` 为一次扫描提供独立生命周期；GUI 线程继续处理事件，扫描结束再通过 signal 通知界面。当前实现没有把 QWidget 移到 worker 中，避免跨线程直接操作 UI。

## 为什么使用任务队列和线程数上限？

端口数量可能从几个扩大到 `1-65535`。为每个端口创建一个线程会带来大量上下文切换、socket 和内存开销。`Queue` 把端口任务拆开，worker 取到一个任务就处理一个；线程数由界面限制在 `10~300`，既能利用并发 I/O，又避免无界创建线程。并发度不是越高越好，最终速度还受 timeout、操作系统和网络栈影响。

## Qt 信号如何更新 UI？

`PortScannerThread` 定义 `progress`、`result` 和 `finish` 三个 signal。`MainWindow.start_scan()` 将它们连接到 `on_progress()`、`on_result()` 和 `on_finish()`。worker 只发出数据，不直接触碰表格；槽函数在 GUI 对象侧更新进度条、内存中的 `scanned_results` 和 `QTableWidget`。这样把跨线程通信与 UI 操作隔离开。

## 极速模式为何只显示开放端口？

极速模式将 socket timeout 从普通模式约 `0.22s` 缩短为约 `0.075s`，并且只对 `connect_ex()` 返回成功的端口发出结果。大量关闭端口通常是扫描结果中的噪声，省略它们可以减少 signal 和表格更新，让用户更快看到开放端口。它仍然会尝试每个选定端口；“只显示”不等于“只扫描”。

## 安全边界是什么？

工具面向本机 TCP 连通性诊断，目标地址来自本机 IP，不提供远程主机批量扫描、漏洞利用、认证绕过或数据上传。使用者仍必须只扫描自己拥有或明确获准测试的系统，并控制端口范围和并发度。开放端口只是监听事实，不是漏洞证明；扫描结果也可能包含主机信息，不应公开发布。

## 生产版可以如何改进？

可以按风险和可维护性分阶段改进：

1. 将扫描核心、输入解析和 UI 拆成可测试模块，加入单元测试和集成测试。
2. 用明确的取消 token、可中断 socket 和可靠的 worker 生命周期，补全停止、异常和窗口关闭路径。
3. 增加结构化日志、扫描会话和权限/审计策略；敏感结果默认脱敏并加密保存。
4. 让目标、协议、超时、重试和并发策略可配置，并对全端口等高成本操作增加更明确的资源预算。
5. 在授权前提下设计远程目标白名单和速率限制；仍然不把端口状态直接等同于安全结论。
6. 增加结果排序、过滤、导出格式和可观测的统计指标，同时保持 GUI 更新批处理，避免大量结果时频繁重绘。
