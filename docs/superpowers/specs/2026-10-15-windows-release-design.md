# Windows 可执行文件发布设计

## 目标

为端口扫描工具增加可直接下载的 Windows `.exe` 发布方式，同时保持源码仓库轻量，不把构建产物提交到 Git。

## 方案

使用 GitHub Releases 发布构建结果：

- 使用现有 `端口扫描系统软件.spec` 生成窗口版 `端口扫描系统软件.exe`；
- 将 `.exe` 作为 Release 附件上传；
- 同时生成 SHA-256 校验文件，方便下载者验证文件完整性；
- README 增加指向 `releases/latest` 的下载入口；
- README 保留从源码创建虚拟环境、安装依赖和自行构建的说明。

## Release 内容

Release 使用明确的版本号，例如 `v1.0.0`，并包含：

- `端口扫描系统软件.exe`
- `端口扫描系统软件.exe.sha256`

Release 说明包含系统要求、主要功能、构建来源、校验命令、安全边界和当前限制。`.exe`、`build/` 和 `dist/` 不进入源码 Git 历史。

## 验证流程

1. 运行 Python 语法检查和敏感信息扫描；
2. 使用 PyInstaller 和现有 spec 构建窗口版程序；
3. 确认 `.exe` 文件存在且大小合理；
4. 计算 SHA-256，并用独立命令重新计算进行比对；
5. 启动程序确认窗口能够打开；
6. 检查 Git 跟踪列表，确认没有构建产物；
7. 创建 GitHub Release 并上传两个附件；
8. 打开 Release 页面，确认 README 下载入口和附件可访问。

## 用户体验

README 的下载区域应优先引导 Windows 用户下载 Release 附件，并明确：

- 该程序面向 Windows；
- 首次运行可能触发 Windows 安全提示，用户应确认文件来源和校验值；
- 程序只进行本机 TCP 端口连通性探测；
- 使用者必须只扫描自己拥有或明确获准测试的系统。

## 不在范围内

- 不将 `.exe` 提交到源码仓库；
- 不引入自动更新器；
- 不提供远程扫描、漏洞检测或云端上传；
- 不改变现有扫描器的核心行为。
